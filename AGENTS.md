# Kaktus working contract

Communicate with the owner in Czech, informally. Work as their senior engineering partner.

- The public program is `taxy-cli`: document and invoke application commands as `taxy-cli <command> ...`, with the same interface in npm bin and standalone `dist/taxy-cli.mjs`. Npm scripts own development/tooling, not alternative application commands. This applies to every integration and working thread.
- README setup uses a local prebuilt-bundle installation and `npx taxy-cli`. Installing `./dist` inside the source checkout must use `--no-save --package-lock=false`; never persist a dependency on the project's own build output. Bundle creation remains explicit through `npm run build` or `npm run check`.
- Target submission commands use `import`; target-file generation uses `export`. Keep these public command names consistent instead of introducing synonyms such as `write` or `send`.
- Normalization and target execution are independent operations with separate receipts/logs that must be reviewed. An optional report tool may aggregate their outcomes and vendor responses, but must not couple the processing flow. Report aggregation is a potential improvement, not a current implementation requirement.
- Mise only pins Node/npm tooling. Keep all runnable project scripts in package.json and invoke them through `npm run <script>`; do not duplicate them as mise tasks. Do not introduce argc, Bash dependencies, coreutils or platform-specific command wrappers. The distributed program needs only Node.
- Keep README.md compact and comfortably below the assignment's 400-word limit. Preserve supplied archived development/evidence links; keep detailed protocol findings in docs/.
- Flat semantic domains: `src/<domain>/<kind>/<owner>`. Exact imports, no barrels, generic utilities, forwarding APIs or speculative frameworks.
- Total synchronous value operations use `Fn`; operations with failure, dependencies, I/O, async work or lifecycle use `Fx`. Use named `Effect.fn` at meaningful orchestration/failure boundaries and `Effect.fnUntraced` in routine per-record/per-event hot paths.
- Source kinds are `fn`, `fx`, `schema`, `error`, `service`, `layer`, `command` and `flag`; the CLI entrypoint is the only exception. Streams are execution values, not a separate `stream/` kind. Their `create*StreamFx` factories live in `fx/`, return Effects with truthful A/E/R and retain bounded, lazy reading. Consume them through `Stream.unwrap` so acquisition and release belong to the stream scope. Named private callables also use `Fn` or `Fx` according to their execution representation.
- Preserve truthful Effect A/E/R. Expected failures are concrete tagged errors. Defects and interruption remain distinct; no assertions, `any`, erased requirements or catch-to-success shortcuts.
- Zod owns data contracts. Every object schema is standalone, named and in its own file; compositions reference those schemas. Export `FooSchema`, `type FooSchema = typeof FooSchema` and `namespace FooSchema { type Type = z.infer<FooSchema> }`. Business objects are strict and carry metadata. Keep raw input validation separate from write admission.
- Known record types and origins use named Zod enums; variants derive their discriminators from those enums. Use `ts-pattern` with `.exhaustive()` for variant decisions. Biome's Serakki `no-switch` rule enforces this direction.
- Every source adapter emits the same intermediate envelope with enum routing and provenance, and unknown business values. Intermediate NDJSON is also a supported input. Only accounting-domain validation admits complete data; never silently coerce or default invalid business values. Strict batches withhold the complete output on rejection. Explicit `--best-effort` may omit independently rejected records, including output validation/size rejections, only after synchronized diagnostics and a required precommit summary. Receipts and audits must report the policy, accepted/rejected counts and required log review. No valid records means no publication after rejection. Framing, decoding, I/O, lock and ambiguous identity failures remain fatal; preserve atomic publication of the admitted subset.
- Admitted records are immutable. A repeated identity never implicitly authorizes replacement. Compare the current domain record through its normalized intermediate projection with admitted incoming data, reporting direct business properties only. Ignore provenance for business comparisons and never resolve related records.
- Public output belongs to `record-export`, separately from domain and loose input contracts. Output schemas select explicit fields, sharing their value policies; mappers project every nested object explicitly. Never serialize domain objects directly. Validate the projected wire record before encoding, preserve provenance and exact values, and keep intermediate output readable by our own importer. Input and output record limits are independent.
- Decimal boundaries use plain strings with at most four fractional digits; domain amounts and exchange rates use Effect BigDecimal. Admission and output reject excess precision without rounding; output normalizes spelling, including zero and trailing zeros. Never route amounts through JavaScript number or silently divide, truncate or reduce scale. Source adapters must preserve DBF text and JSON monetary tokens before decoding; native numeric money is rejected at admission. Arithmetic may retain extra intermediate digits, but publishing requires exact admission. Explicit rounding needs a separately agreed business policy. Decimal text is bounded to 1 MiB, independently of the record limit. JSON Schema exports describe admission text rather than in-memory BigDecimal objects.
- Keep identifiers, domain fields, comments and documentation in English. Preserve foreign field names only in exact import/protocol contracts; mapping into the domain is explicit.
- Process input/output incrementally with backpressure and bounded records, chunks and concurrency. Never collect complete datasets or build unbounded lookup sets in memory.
- Stream the primary human processing log to a retrievable file with backpressure; stderr is secondary. Append and synchronize events progressively, separately from atomic data output. A rejected diagnostic write must never replace the original failure or turn an already committed publication into a failed write. The data destination must differ from the log file.
- Audit operations with a caller-declared actor and operation ID. Persist intent before reading business data; append and synchronize a separate audit file. Canonical log/audit entries are typed contracts, rendered through human-text printers by default. JSON remains the explicit data-exchange format. Failed completion audit after publication must be reported separately without denying a successful publication.
- Our output is published only after its complete stream succeeds. Stage on the destination filesystem, flush, close, then replace atomically. A success means the complete output is published. External Kaktus writes are best effort; do not promise target rollback.
- Assume target exclusion for the whole company is provided externally; implementing locks/concurrency is outside the agreed exercise scope. Never bypass another user's lock or treat a busy-state precheck as proof of exclusive access throughout an import. Offline XML generation does not access target DBF files.
- Kaktus writing consumes only the shared intermediate NDJSON through the common reader; source-specific adapters run separately and never enter target orchestration. Resolve client/buyer/live company identity before target execution. Prepare all XML before the first target call; each file contains one company and at most 20 invoices. Fresh, complete target data is the replay authority: missing identities may be imported, exactly one matching invoice is ALREADY_PRESENT, changed properties are conflicts and ambiguous identities are refused. Identity is company, supplier registration number (otherwise exact name), and supplier invoice number. Compare normalized persisted invoice properties, excluding target-assigned IDs, provenance, payment state and related supplier details that this protocol cannot update. Read back after each submitted batch, including failed/missing responses; an acknowledgement alone never confirms a write. Restart from the original immutable input with a fresh target view, without a local intent ledger or stale writer lock. Retained run directories are evidence only. Assume target exclusion is provided externally; implementing locks/concurrency is outside this exercise's agreed scope. Corrupt or unreadable target data stops confirmation and needs external recovery.
- Use portable Node/Effect filesystem and process APIs. No OS branches, shell-based file operations, hardcoded separators or native runtime dependencies.
- One Node runtime root composes the actual dependencies. Services/Layers own real capabilities or lifecycle, not ordinary domain logic.

Future tests live in `test/` and protect meaningful regressions, not implementation details. Use `npm run check`; commands must work on Windows, Linux and macOS.
